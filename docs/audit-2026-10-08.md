# Maintainer audit and regression evidence — 2026-10-08

Scope: hosted browser/API flow, read-only RPC adapter, receipt and source normalization, current-state assertions, IndexedDB/SQLite persistence, exported evidence, publication configuration, CI, and submission claims. This is a maintainer code audit, not an independent security certification or a smart-contract audit.

## Accepted limitations, not hidden fixes

The public API has per-instance admission limits, not a global distributed quota. No custom WAF policy or external alert/drain configuration has been established. This is a bounded public developer-tooling beta, not a production multi-tenant abuse-control guarantee. Cross-origin checks do not authenticate non-browser callers. `gen_call` views may consume computation even without chain writes. Higher-volume deployment needs global platform-level limits and monitoring.

Inputs must be public. Pattern-based credential rejection/redaction is not perfect secret detection; manually review exports. Browser storage can be cleared by the user/browser. Older damaged records are preserved and not migrated or automatically deleted. An integrity-valid ZIP is not necessarily a truthful or authored report.

Official checks: Vercel [overwrites its forwarded client IP headers](https://vercel.com/docs/headers/request-headers); therefore header spoofing was not recorded as a confirmed hosted finding. Receipt enums were checked against the [official GenLayer receipt reference](https://docs.genlayer.com/api-references/genlayer-node/gen/gen_getTransactionReceipt). No new blockchain transaction, private key, appeal, or finalization was used in the audit.
